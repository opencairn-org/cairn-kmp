# 3. Proto RPC only, over the Connect protocol

Date: 2026-10-28

## Status

Accepted

## Context

cairn-core serves its `cairn.v1` protos through Connect-Go handlers (Connect, gRPC and
gRPC-Web on the same routes) and a parallel REST surface for the web UI. Only part of the RPC
surface is implemented today; `docs/handover.md` asks core for the rest. There is no Kotlin
Multiplatform Connect client library; connect-kotlin is JVM/OkHttp only. gRPC framing carries
the status in HTTP trailers, which neither Ktor nor URLSession expose.

## Decision

- The client speaks the proto RPC API exclusively. No REST client exists in this repository.
- Messages and service stubs are generated by Wire from the protos vendored in `proto/` at a
  pinned cairn-core tag (`PROTO_VERSION`).
- The transport is a small implementation of Wire's `GrpcClient` over Ktor speaking the
  Connect protocol (unary: `POST /<pkg>.<Service>/<Method>` with `application/proto`; streams:
  `application/connect+proto` envelopes). HTTP/2 comes from the OkHttp and Darwin engines.
- Binary content (photos, static maps, exports) is fetched from presigned URLs the RPCs return,
  never through an API endpoint.

## Consequences

Core must implement the handover before the corresponding client phase ships. The transport
is ours to maintain, but it is a few hundred lines against a published, conformance-tested
protocol.
